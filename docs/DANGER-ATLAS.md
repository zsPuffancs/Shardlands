# Dynamic danger geography and World Atlas

Implemented for new frontier descriptors (World Tier 8+) in generator-v2 universes. Restart the server after updating the code. No save deletion or reseed is needed. Already saved region descriptors, spawn plans, characters and generator-v1 worlds retain their existing geography. Creating a danger preview does not upgrade an old region.

## Open the Atlas locally

Start the game normally with `node server.js`, then open **http://localhost:3000/dev/atlas** on the server computer. Use the configured port if different. This is the actual server's developer tool, not a separate app or mockup.

- Choose a persisted, unlocked region from the selector. A saved descriptor without a spawn plan is inspected using an in-memory plan generated by exactly the same helper as gameplay; inspection does not attach or save that plan.
- To inspect an unopened region, enable **Hypothetical dry-run preview**, enter Tier 1-65542 and optionally a different seed, then click **Inspect**. A preview never calls the mutating `regionFor`, unlocks a tier, records history, registers a map, or spawns monsters.
- Wheel-zoom around the cursor, drag to pan, and use **Fit region** to reset. Hover for an exact server-evaluated danger score and category. Click an encounter or position to pin coordinates and its enemy definitions in the inspector.
- Toggle terrain/boundaries, danger, encounters, protected areas, routes and diagnostics separately. Diamonds identify bosses/Alphas, purple squares stones, and small dots camps. Green paths are validated approaches; dashed orange paths are optional shortcuts and are not guaranteed safe.
- **Export map PNG** exports the entire region with the currently enabled layers, seed, status and snapshot identity. **Export validation JSON** includes counts, errors, required objectives, route geometry/length/maximum danger, repair actions and omitted optional placements.

The seven founding zones and existing old regions do not acquire a fictional danger field. Their saved v2 encounter geometry can still be inspected. Generator v1 did not persist encounter definitions, and some legacy runtime stat choices are unseeded: its Atlas view deliberately reports encounter validation as unavailable rather than pretending to reconstruct exact saved enemies. Its real map geometry and region metadata remain inspectable.

## Authority and compatibility

`region-blueprint.js` supplies the local geometry, frontier zone definition and `buildRegionPlan` to both `regions.js` and `world-atlas.js`. Region size and portal position come from `game-world.js`; level rules/content come from the existing monster tables. The Atlas client renders these server descriptors and sampled values; it has no second generator implementation.

The current gameplay terrain is flat and walkable inside the square map edge. Trees and rocks rendered in the game are decorative and do not define server collision. The Atlas therefore shows biome ground, the actual boundary, protected settlement, spawn definitions and paths; it does not invent mountains, collision meshes or unreachable valleys. Adding solid terrain later must extend the same shared navigability predicate and graph validator.

The existing layout/spawn-plan version remains 2. A separately versioned `region.dangerSpec.version = 1` opts **new** v2 frontier descriptors into danger geography. No danger spec means exact old placement behavior. A materialized plan persists its actual `danger` field, paths and encounter definitions. Unknown saved danger versions are refused by runtime loading without rewriting the save. Pure `generateRegion` compatibility outputs and v1 fixtures remain intact; `createRegionDescriptor` applies the new, independently versioned policies for newly persisted descriptors and dry runs.

The level-range update also remains independent: new frontier ranges span 20-45 levels, existing ranges remain unchanged, and the level-10000 ceiling is preserved. XP/drop rules are independent of danger geography. No HP, damage, player combat or population scaling formula changes were introduced by danger geography.

## Mathematics

For region-local coordinates `(x,y)`, danger is

    D = clamp(B + N + A - S, 0, 1)

`B` is the biome baseline. `N` interpolates an 8x8 seeded value lattice using the cubic smoothstep `s(t)=t*t*(3-2*t)` in both axes. This is coherent low-frequency noise with continuous first derivatives across lattice cell boundaries, not independent noise at each sampled point. `A` sums compact threat kernels `strength * s(clamp(1-distance/radius))` for territories, rare anomaly landmarks and the placed mandatory boss arena. Each purpose has an independent SHA-256 counter stream, including `danger-geography`; generating a heatmap consumes no layout randomness.

`S` is a combination of respite kernels and the maximum applicable protected-area/corridor safety contribution. Protected disks target danger at most 0.10, fading smoothly over a 300-unit shoulder. Safe corridors target 0.32 on their centreline, with a smooth 95-unit half-width; the final boss approach rises smoothly to at most 0.78 at its destination. Safety is derived from raw danger, so a high baseline cannot overwhelm a protected entry or the centre of a repaired corridor. There are no discontinuous category-based stat changes. Scores are categorized as SAFE `[0,.20)`, LOW `[.20,.40)`, NORMAL `[.40,.65)`, HIGH `[.65,.85)`, EXTREME `[.85,1]`.

Locations, radii, strengths, respite arrangement and approach angle vary deterministically. The descriptor freezes these parameters instead of reevaluating mutable history later. Nothing gets harder merely because a player stays longer.

`config.json` may include `worldGeneration.danger.baseline` and `.noise`. They are frozen in universe generation settings when first established; baseline is bounded to .25-.65 and noise to .05-.25. Defaults preserve biome-specific profiles. Settings do not retrofit saved danger descriptors. Existing v2 settings that predate danger capture these two options once on startup.

## Routes and encounters

Mandatory points are the settlement/entry, the actual portal and each mandatory World Boss arena. An eight-neighbour 41x41 navigation graph uses the gameplay walkable map rectangle. Edge traversal is checked at intervals of at most 25 units, including the connectors to exact objective coordinates. Other mandatory arenas are excluded from a route. Dijkstra uses Euclidean segment length weighted by `1 + 10*D^2`, with a binary heap. A seeded approach waypoint encourages a nonradial route; a distance-first alternative provides the optional shortcut.

Generation first attempts a route avoiding EXTREME danger. If this fails, it deterministically searches the traversable graph allowing high danger, carves a smooth safety corridor along the result, records the repair and revalidates every mandatory connection. Physically impossible mandatory points reject generation before a plan is installed. Required objectives are never silently omitted. There are no terrain obstacles to repair in the present game; externally corrupted objective geometry is diagnosed rather than persisted as a valid map.

Boss arenas are reserved first. Before optional encounters are placed, safe route footprints are reserved with encounter-radius clearance. Camps require .23-.84 local danger, Alphas at least .65, and stones/resources at least .20; initial boss arena candidates require .50-.85 before their own attraction is added. Existing protected-area, spacing, finite-attempt placement and bounded budget checks still apply. Optional placements may underfill and are reported. Anomalies are geographical threat landmarks, not additional always-active monster populations.

No new per-monster or per-tick noise work is performed. The same existing encounter runtime activates nearby spawn definitions and unloads idle ones. Planned safe corridors are not invulnerability zones: monsters can still chase a player onto a path. The Atlas is a developer tool; paths are not added to the normal player HUD or rendered as new physical road assets.

## Bounds, caching and preview semantics

A field evaluation costs `O(T+R+L)`: threat/respite count plus safe-route segment count. All are bounded per region. Graph generation uses a fixed 1681 vertices and at most eight edges per vertex with a binary heap (`O(V log V)` heap work plus bounded edge sampling). No operation generates all preceding tiers to preview one tier. V2 generation snapshots copy six element counters and scalar event totals, never the growing per-boss ledger.

The display heatmap defaults to 96x96 and is capped at 128x128. Hover probes use the exact shared danger function, not the display approximation. The Atlas keeps an LRU of at most eight results, keyed by seed, tier, generator/settings, saved descriptor/plan identity, frozen history/range context and preview mode. No GPU resources, timers or heatmaps are retained for previous selections by the client; it replaces its one offscreen heatmap canvas. Export creates one temporary bounded canvas.

A server-start Atlas snapshot freezes the historical counters, generation settings and previous-level context for hypothetical previews. The UI/report identifies this snapshot. Previews are scenarios, not predictions of unknown future kills or content/plugin changes. Alternative seeds have no saved previous-region context, so they use the level policy's independent tier fallback. Restarting the server establishes a new frozen preview context. Persisted-region inspection always takes the saved descriptor/plan rather than replacing it with the hypothetical scenario.

## Access control

The project's administrator mechanism is bound to authenticated game WebSocket connections and has no secure HTTP admin session. The Atlas therefore uses the requested local-only fallback: direct loopback connections with an explicit localhost/loopback Host, same-origin requests, and no forwarding headers. Remote addresses, proxy headers, hostile Host values and cross-site Origins are rejected with 403. No game hero name is accepted as HTTP authorization. All Atlas data and even its static files go through this guard and have no-store/CSP/frame restrictions. Atlas assets are outside `public/`.

Do not proxy or tunnel this route. A trusted local proxy that strips forwarding headers and rewrites Host cannot be distinguished from a local client; remote deployment needs a genuine authenticated HTTP admin session before this restriction can be relaxed. The public `/api/info`, universe identity and chronicle response no longer include the full universe seed, danger descriptors, spawn plans or internal generation snapshots. The client retains its existing derived numerical scenery seed for rendering.

## Verification and measured results

Explicitly requested tests:

    node --test tests/danger-atlas.test.js
    node --test tests/*.test.js

The danger/Atlas suite covers reproducibility, JSON roundtrips, no unseeded generation, old descriptor/plan preservation, bounded history snapshots, all six profiles, continuity, score bounds, nonuniformity, protected disks, role-aware placement, mandatory routes, extreme-barrier repair, impossible objectives, bounded counts/high tiers, preview purity, frozen history after cache eviction, LRU capacity, corrupted-spacing diagnostics and real HTTP data/access/export endpoints. The existing suite continues to check legacy golden layouts and exact lazy-runtime restart behavior. The complete suite has 69 passing tests, including the six prior XP/level-range tests.

A stress test generates 120 named seeds across all six profiles, ordinary/zero/maximal encounter budgets and tiers 8, 80, 65542, 1000000 and Number.MAX_SAFE_INTEGER. Failure output includes the seed, tier and biome. On this Windows machine with Node v26.13.0, generation plus spawn/route validation averaged approximately 12.4 ms, p95 25.2 ms, maximum 32.3 ms in the focused run. These are local measurements, not production latency guarantees. The playable coordinate runtime and Atlas tier selector remain limited to 65542 even though the pure mathematical tests cover larger safe integers.

Real HTTP tests verify the UI assets, region listing, alternative-seed preview, exact probes, report download, malformed queries, proxy/Host/Origin rejection, read-only methods and absence of private generation fields in public responses. Browser visual/interaction verification was blocked by the browser's origin approval gate; no claim of a completed visual check is made. PNG export, wheel zoom and dragging are implemented in the Canvas client, but should receive a manual browser pass locally.

Next useful extensions are a shared terrain collision/navmesh contract if solid terrain is introduced, secure HTTP admin sessions for remote developer access, and a persisted content manifest to make future plugin/content-table changes reproducible too.
