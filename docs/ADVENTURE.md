# Adventure journal, party equipment and recovery

## Player controls

- Open the **📖 Adventurer's Journal** button below the minimap. The journal is a normal draggable window; Escape closes it. It has searchable **Bestiary** and **Village contracts** tabs, plus a Refresh button. The encampment/village funding board also links to contracts.
- A bestiary family is discovered by hitting an enemy or collecting its actual dropped loot. Kills are credited to eligible encounter contributors, independent of the XP level-gap cutoff. Generated variants are grouped by their authoritative archetype. The journal lists encountered categories, observed level range, signature attack names, kills and the quantities of actually collected drops. It does not publish undiscovered encounters, map locations or seeds. An entry discovered through loot alone can have no observed level or kills.
- Manage contracts near a village Merchant, Blacksmith, Soul Mystic or an encampment/funding board. Each character can hold one contract. A contract belongs to the region where it was accepted and must be claimed there. **Clear the wilderness:** 12 ordinary/Alpha enemies, 2 Souls. **Break Spirit Stones:** 2 stones, 3 Souls. **Defeat a boss:** 1 regular/World Boss, 5 Souls. These are separate modest quest rewards; monster rewards, XP and prices are unchanged.
- Progress requires a qualifying encounter contribution, a kill in the accepted region, a nonsummoned enemy, and a level gap below 13. Pre-acceptance kills do not count. Completed contracts require deliberate reward collection; abandoning requires an in-game confirmation. A full Souls wallet leaves the reward claimable. Duplicate requests cannot pay twice.
- Contracts and claim history reset at **00:00 UTC**, including unfinished work. Each kind can pay once per region per day. The server checks the UTC boundary once per second through the existing tick and sends open journals a full replacement state, including empty active work and renewed offers. Failed delivery is retried at a bounded rate. Buttons update when the character dies, respawns or moves into/out of trader range; claim requests still revalidate everything on the server. Kill progress updates live.
- In **Team**, the leader can switch **Equipment drops** between **Last-hit player** (the unchanged default) and **Round robin**. Round robin follows team membership order among nearby living members with bag space and advances once per actual equipment drop. A recipient's class determines its weapon family, and the existing 25-second ownership protection remains. Full teams/bags do not duplicate or delete drops: if no eligible recipient has space, ownership falls back to the killer. Gold distribution, Souls, consumables, existing trade and the sharing toggle retain their existing behavior. Turning XP/gold sharing off also disables round robin. The setting is transient like the team itself.

## Combat and crafting UI

The selected boss frame displays authoritative phase (1–3), cast name/progress, World Boss enrage countdown/state and the recovery vulnerability window. Cast/phase messages have separate elements and timers so a phase change cannot erase an attack warning. Timing uses snapshot server time plus elapsed monotonic client time, rather than assuming that player clocks agree. Stale connection data is hidden after three seconds. New fields participate in the existing monster field-delta protocol; no per-frame server broadcasts were added.

Affix tooltips, manual Mystic affixing and Auto Affix show the configured combined gear caps. Lifesteal remains capped at 15%, gear attack speed at 40%; no costs or affix ranges changed. The detailed item/target estimate excludes the outgoing item in the same slot and shows effective equipped totals and the wasted portion. A large raw affix value is never described as equivalent effective power. Caps come from the same server constants as combat. Passive lifesteal/haste are separate mechanics and are not included in these gear-only totals.

World information and team help now use live scaling metadata instead of the obsolete fixed 3× World Boss HP / 1.5× party scaling descriptions. Boss multipliers are relative to the level power budget and remain separate from archetype, world-depth, server-rate and party multipliers.

## Persistence and limits

The original `saves.json`, `plugin-data.json` and `universe.json` schemas remain usable. All runtime store saves now go through one coordinator. Before snapshotting, it captures every online player and active encounter. It writes a full `save-journal.json` redo checkpoint by temporary-file rename, writes each existing store from that frozen snapshot, and removes the journal only when all writes succeed. Requests arriving during IO cause a subsequent checkpoint before the shared save promise completes. Partial failure preserves the redo file; the next save retries current state. On startup a journal is replayed into all three stores **before** they are opened; malformed journals stop startup and preserve the files. Backups taken while the server runs should include the journal when it exists, or be taken after a clean shutdown. This is process-crash recovery, not a guarantee against disk corruption or hardware failure.

This prevents a stall contribution being committed independently of its wallet deduction. Donor dictionaries are normalized to null-prototype objects on each funding mutation, including after loading JSON; `constructor`, `__proto__` and `toString` are ordinary names. Contribution inputs and wallet balances must be safe integers. Existing contributions and stall ownership are retained.

Encounter snapshots now preserve elapsed fight time and remaining recovery. Unloading/restarting pauses the saved fight clock rather than resetting it, so an enraged World Boss remains enraged. Legacy wounded snapshots with no clock start one when loaded. Fully reset/respawned encounters clear their timer and recovery. An interrupted cast is cancelled on reload, preserving the existing cast-recovery policy rather than replaying an invisible attack.

The bestiary and daily quest ledger live in existing `player.data.adventure` (version 1). Old characters start with an empty journal; no migration or world regeneration is needed. There are at most 256 discovered families, 32 drop categories and 8 signature attacks per family, counters saturate at one billion, and the daily claim ledger is bounded at 256 claims. Contract acceptance/abandonment/claim requests request a coordinated save; ordinary kill/drop observations use the normal player-save lifecycle. Unknown future adventure versions are not silently rewritten.

Journal updates are sent only while the window is open and are batched at most once per 250ms per player. A batch contains the latest changed entries and contract progress, rather than a full book for every hit or pickup. Closing discards the transient queue; reopening requests authoritative state. No timer or job is allocated per hit.

## Trade offer integrity

Offering an item reserves its UID against manual affixing, rerolling, locking, equipping, selling, forging and merging. Bulk selling/merging skips offered items; destruction and Auto Affix retain their existing reservation checks. Remove an item from the offer to modify it. Other equipment and consumables remain usable.

The trade service captures each offered item's object identity and a SHA-256 fingerprint of its serialized state. Both confirmations and final execution revalidate unique ownership, unlocked status, external reservations and the captured state. An external/plugin mutation, replacement, lock or duplicate UID refreshes the offer and revokes both acceptances before any transfer. Confirmations must echo the current trade ID and offer revision, so an in-flight old confirmation cannot accept a replacement offer. Both players must review and accept the new offer. Older clients must refresh before confirming trades. This is transient trade state and does not change the save format.

## Verification

Per the user's standing instruction, **tests were not run for this change**. Prepared regression cases are in `tests/adventure-improvements.test.js` and cover partial-write recovery, saves requested during IO, malformed journal preservation, reserved-looking donor names after JSON round trips, boss unload/reload, actual boss field-delta decoding, cap calculations, round-robin eligibility, daily contracts, duplicate claims, discovery/drop persistence and Hungarian localization. Existing suites remain available for explicit execution with `node --test tests/*.test.js`.

JavaScript syntax and Git whitespace checks were performed. Browser layout and gameplay still need an explicit manual verification pass; no live save files were edited for verification.

Follow-up regression cases for offer reservations/fingerprints, UTC rollover, delivery retries and actual journal HUD access changes are prepared in `tests/trade-journal-regressions.test.js`. They have **not been executed**, per the same standing instruction.
